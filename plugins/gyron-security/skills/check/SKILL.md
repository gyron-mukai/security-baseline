# セキュリティ点検（株式会社ジャイロン 共通）

社員の Mac が、会社として決めた**最低ライン**を満たしているかを点検し、足りないところの直し方を案内する。
利用者の多くは非エンジニア。専門用語は言い換え、1回に1つずつ進める。

## 守ること
- **点検は読み取りだけ。** 設定の変更は、本人に内容を説明して了承を得てから行う
- `sudo` が必要な操作は Claude からは実行しない。本人にターミナルで実行してもらう（`references/remediation.md` に手順あり）
- パスワード・復旧キー・トークンなどの**中身を聞かない・表示しない・保存しない**。「あるか・どこに置いているか」だけを扱う
- 合否は `check.sh` の結果を正とする。Claude が独自に判定を変えない（説明を補うのはよい）
- 点検結果は本人の PC の中にだけ保存する。外部サービスに送らない

## 手順

### 1. はじめに（1〜2行で伝える）
「Mac の安全設定を確認します。読み取りだけで、勝手に設定は変えません。点検は10分ほどです。見つかった点を直す作業はさらに時間がかかるので、今日は点検だけにして、直すのは次回でも大丈夫です」

### 2. 機械判定と棚卸し（並行して実行）
- `${CLAUDE_PLUGIN_ROOT}/scripts/check.sh` — 全員共通の最低ライン。✅ 合格／❌ 必須の不合格／⚠ 推奨の不合格
- `${CLAUDE_PLUGIN_ROOT}/scripts/inventory.sh` — アプリ・拡張機能・常駐物など、人によって違う部分の一覧
- `os-update` は Apple への問い合わせで数十秒かかることがある

### 3. アカウントの確認（AskUserQuestion で質問する）
機械では確認できない項目。答えは「はい／いいえ／分からない」だけを記録する。
1. 会社の Google アカウントで2段階認証を使っているか
2. Apple ID（iCloud）で2段階認証を使っているか
3. GitHub を使っている場合、2段階認証を使っているか
4. パスワードの管理方法（パスワード管理アプリ・Apple のパスワード／ブラウザに保存／メモやファイルに書いている／覚えている）
5. 2段階認証の**リカバリーコード（予備のコード）**をどこに保管しているか（パスワード管理アプリ／紙／PC 内のファイル／保管していない）

「メモやファイルに書いている」「PC 内のファイル」と答えた場合は、パスワード管理アプリ（Apple の「パスワード」アプリなど）へ移し、元のファイルはゴミ箱に入れてゴミ箱を空にするよう勧める。

### 4. 棚卸し結果の読み方
次の観点で、気になる点だけを拾う（全部を説明しない）。
- **ブラウザ拡張機能（全サイト権限）**: すべてのサイトの中身を読み書きできる。知らない・使っていない・名前が ID のままのものは削除を勧める。業務で使うものは残してよい
- **アプリ**: 「（Electron）」付きは中に Node.js を持つ。`references/advisories.md` に該当があれば照合する。明らかに古いバージョンなら更新を勧める
- **常駐物（LaunchAgents/Daemons）**: 名前から何のソフトか分からないものは、本人に心当たりを聞く。会社が入れたセキュリティソフトなどは触らない
- **外部から接続を受け付けているプロセス**: 心当たりのないものは本人に確認する。`rapportd`（Apple の連携機能）や Docker/OrbStack の 80/443 番は、開発用途なら問題ない
- **Homebrew の更新待ち**: 50件を超えていたら `brew upgrade` を勧める
- **平文の秘密情報らしきファイル**: ファイル名だけを伝え、中身は開かない。手順3と同じく移行と削除を勧める
- **前回の点検**: 30日以上空いていたら、月1回の点検を勧める

### 5. その時々の脆弱性
`references/advisories.md` を読み、対象期間内の項目を棚卸し結果と照らし合わせる。

### 6. 結果の説明と直し方
1. まず全体を一言で（例: 「必須16項目のうち2つが未対応です。どちらも5分で直せます」）
2. **❌ 必須 → ⚠ 推奨 → 棚卸し・アカウントの指摘** の順に、1件ずつ説明する
3. 直し方は `references/remediation.md` の該当 ID を使う。画面操作は1手順ずつ案内し、本人の「できた」を待ってから次へ進む
4. アプリの更新は、アプリごとにメニューの場所が違い見つけにくい。`references/remediation.md` の「アプリの更新」の探し方を案内する
5. 本人が「今はやらない」と言った項目は無理に進めず、レポートの「残り」に入れる
6. 直し終わったら `check.sh` をもう一度実行して ✅ を確認する

### 7. レポートの保存
`~/Documents/セキュリティ点検/YYYY-MM-DD.md` に保存する（フォルダが無ければ作る）。保存する前に、保存先を本人に伝える。

```markdown
# セキュリティ点検 YYYY-MM-DD

## 最低ライン（check.sh）
（最終実行時の表をそのまま貼る）

## アカウント
- 会社Google 2段階認証: はい／いいえ／分からない
- Apple ID 2段階認証: …
- GitHub 2段階認証: …（使っていなければ「対象外」）
- パスワード管理: …
- リカバリーコードの保管: …

## 棚卸しで見つかった点
- （指摘と、本人の判断（削除した・残す理由））

## 今回直したこと
- …

## 残り（次回までに）
- …
```

最後に「次は1か月後に、また『セキュリティ点検して』と話しかけてください」と伝えて終える。
